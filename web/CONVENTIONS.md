# Frontend conventions

How pages in `web/` are built. Reference implementations: `src/pages/activities/index.tsx` and
`src/pages/activity/index.tsx`.

## Structure

- One directory per page: `src/pages/<name>/index.tsx` (default export) plus any page-local
  components next to it. Routes live in `src/app/router.tsx`.
- Shared building blocks: `src/components/` (`Chart`, `MapView`, `SportIcon`/`SportBadge`, `ui.tsx`:
  `Card`, `PageHeader`, `StatTile`, `Sparkline`, `StatusPill`, `Segmented`, `LegendItem`,
  `ScrollArea`, `Skeleton`, `EmptyState`, `ErrorState`, `QueryState`, `Delta`) and `src/lib/`
  (`format`, `charts`, `tokens`, `sports`, `range`, `preferences`, `geo`).

## Data

- Always use the typed client: `api.useQuery("get", "/api/...", { params: { query } }, { enabled: range.ready })`.
  Response types: `Schemas["ModelName"]` from `@/api/client`. The schema file is generated by
  `scripts/gen_api_types.sh` — never edit it.
- Global filters come from `useRange(defaultPreset)`: `range.query` (`{start, end}`), `range.sport`.
  Pages with a sport filter are flagged in `src/app/nav.ts`.
- The API speaks SI units (m, s, m/s, kg, W, bpm, °C). Convert only for display with
  `src/lib/format.ts` and `useUnits()`.

## Layout

- `PageHeader` (title + one-line description) first; then a row of `StatTile`s
  (`grid grid-cols-2 gap-3 md:grid-cols-4`), then `Card`s in a responsive grid
  (`grid gap-5 lg:grid-cols-2`, wide charts `lg:col-span-2`).
- Mobile first: nothing may overflow horizontally at 390 px. Tables go in `ScrollArea`.
- Loading → `Skeleton`, error → `ErrorState`, no data → `EmptyState` (never an empty chart).

## Charts (ECharts via `<Chart option ariaLabel height />` only)

- Use the builders in `src/lib/charts.ts` (`line`, `bars`, `scatter`, `refLine`, `axisTooltip`,
  `valueYAxis`, `GRID`, `tooltipRow`) so marks are consistent: 2px lines, 10 % area wash, bars
  ≤ 24px with 4px rounded data-ends, 2px surface gaps in stacks, hairline recessive axes.
- Colour by job: sports → `sportColor(group, mode)` (fixed slots, stack in `bySlot` order);
  magnitude → one-hue blue ramp (`SEQUENTIAL`, `ZONE_RAMP` for ordinal zones); polarity →
  `DIVERGING` (blue ↔ red, gray midpoint); state → status colours only with icon + label
  (`StatusPill`); sleep stages → `SLEEP_STAGES`. Text never wears a series colour — use
  `CHROME[mode]` ink tokens in options. Never hardcode black/white.
- One y-axis per chart. Two measures with different scales → two charts (stacked, linked with the
  `group` prop) or small multiples.
- A legend for ≥ 2 series; label selectively (end value, extremes), never every point.
- Crosshair tooltips (`axisTooltip`) on lines/areas, item tooltips on bars/dots/cells.
- Every chart needs a meaningful `ariaLabel`; both light and dark mode must look right.

## Verification (run before calling a page done)

- `pnpm -C web exec tsc -b --noEmit` · `pnpm -C web exec eslint . --max-warnings=0` ·
  `pnpm -C web exec prettier --check .`
- `bash scripts/e2e_dev.sh <api-port> <web-port> "page <name>"` — all four variants
  (desktop/mobile × dark/light) must pass: charts drawn with data, maps loaded, no console errors,
  no horizontal overflow, no serious/critical axe violations.
- Look at the screenshots in `artifacts/screenshots/<variant>/<page>.png` and fix what looks off
  (overlapping or clipped labels, cramped or empty areas, illegible text in either theme).
