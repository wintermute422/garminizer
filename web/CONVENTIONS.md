# Frontend conventions

How pages in `web/` are built. Reference implementations: `src/pages/activities/index.tsx` and
`src/pages/activity/index.tsx`.

## Structure

- One directory per page: `src/pages/<name>/index.tsx` (default export) plus any page-local
  components next to it. Routes live in `src/app/router.tsx`.
- Shared building blocks: `src/components/` (`Chart`, `MapView`, `SportIcon`/`SportBadge`, `ui.tsx`:
  `Card`, `PageHeader`, `StatTile`, `Sparkline`, `StatusPill`, `Segmented`, `LegendItem`,
  `ScrollArea`, `Skeleton`, `EmptyState`, `ErrorState`, `QueryState`, `Delta`), `kit.tsx`
  (`MetricTile`, `Spark`, `Change`, `Stepper`, `FactRow`) and `src/lib/` (`format`, `charts`,
  `tokens`, `status`, `stats`, `wallClock`, `sports`, `range`, `queries`, `preferences`, `geo`).
  Pages never import another page's internals; anything two pages need moves here.

## Data

- Always use the typed client: `api.useQuery("get", "/api/...", { params: { query } }, filters.options)`.
  Response types: `Schemas["ModelName"]` from `@/api/client`. The schema file is generated by
  `scripts/gen_api_types.sh` — never edit it.
- Global filters come from `usePageFilters()` (`src/app/pageFilters.ts`): `filters.query`
  (`{start, end, sport?}` for sport-filtered endpoints), `filters.dates` (`{start, end}`),
  `filters.sport`, `filters.options` (`{enabled, placeholderData}`). Which filters a page has and
  its defaults (`defaultPreset`, `defaultSport`) live only in its `src/app/nav.ts` entry.
- Loading / error / content of one or several queries: `<QueryState query|queries>` (any pending →
  skeleton, first error wins); hand-roll only where a page deliberately renders partial data.
- The API speaks SI units (m, s, m/s, kg, W, bpm, °C). Convert only for display with
  `src/lib/format.ts` and `useUnits()`.

## Layout

- `PageHeader` (title + one-line description) first; then a row of `StatTile`s
  (`grid grid-cols-2 gap-3 md:grid-cols-4`), then `Card`s in a responsive grid
  (`grid gap-5 lg:grid-cols-2`, wide charts `lg:col-span-2`).
- Mobile first: nothing may overflow horizontally at 390 px. Tables go in `ScrollArea`.
- Loading → `Skeleton`, error → `ErrorState`, no data → `EmptyState` (never an empty chart).

## Styling (Swiss minimal; tokens in `src/styles.css`, chart mirror in `src/lib/tokens.ts`)

- Never hard-code colours, radii, shadows or font sizes in components; use the token utilities.
  New needs get a new token in `styles.css` (both modes, both dark blocks), not an arbitrary value.
- Colour: `bg-page` / `bg-surface` / `bg-surface-2|3`, ink `text-ink|ink-2|ink-3`, hairlines
  `border-line` (`border-line-strong` for inputs/dashed empties), `border-rule` for the strong ink
  rule (page header, emphasised panels). Accent is for data, focus and the active-nav bar; link text
  on hover uses `text-accent-text`. Primary buttons `bg-action text-on-action hover:bg-action-hover`;
  destructive `bg-danger text-on-danger`.
- Interaction: `hover:bg-hover active:bg-pressed`; a selected segment/toggle is inverted ink
  (`bg-selected text-on-selected`). Focus is the global 2px `--focus-ring` outline — never remove it.
- Geometry: `rounded-card` (cards, panels, overlays), `rounded-control` (buttons, inputs, rows),
  `rounded-chip` (tags, segments), `rounded-bar` (tracks, progress bars), `rounded-swatch` (legend
  keys); `rounded-full` only for dots and thumbs.
- Elevation: cards are flat (`shadow-card` = none, separated by hairlines); only layers floating
  over content (map panels, drawers, sheets) use `shadow-overlay`.
- Type: Inter (bundled, no CDN). Labels above values: `text-eyebrow uppercase`; captions `text-2xs`;
  figures `text-metric-sm|metric|metric-md|metric-lg|metric-xl|hero` (they carry line-height and
  tracking) with `tabular`; page titles `sm:text-display`.

## Charts (ECharts via `<Chart option ariaLabel height />` only)

- Day-based x axes: `dayX(day)` / `dayPoint(day, v)` (local noon), `dayExtent(start, end)`,
  `dayAxis(min, max)`, `dayTitle(day)`; one-row-per-day tooltips via
  `axisTooltip(dayTooltip(rows, dayOf, render))` (formatters always get the params as an array).
  Round fixed axis bounds: `niceScale`.
- Use the builders in `src/lib/charts.ts` (`line`, `bars`, `scatter`, `refLine`, `axisTooltip`,
  `valueYAxis`, `GRID`, `tooltipRow`) so marks are consistent: 2px lines, 10 % area wash, bars
  ≤ 24px with near-square data-ends (`barEnd()`, `MARK_RADIUS`), 2px surface gaps in stacks,
  hairline recessive axes. Washes and tooltip chrome come from `CHROME[mode]`.
- Colour by job: sports → `sportColor(group, mode)` (fixed slots, stack in `bySlot` order);
  magnitude → one-hue blue ramp (`SEQUENTIAL`, `ZONE_RAMP` for ordinal zones); polarity →
  `DIVERGING` (blue ↔ red, gray midpoint); state → status colours only with icon + label
  (`StatusPill`); sleep stages → `SLEEP_STAGES`. Text never wears a series colour — use
  `CHROME[mode]` ink tokens in options. Never hardcode black/white.
- One y-axis per chart. Two measures with different scales → two charts (stacked, linked with the
  `group` prop) or small multiples.
- A legend for ≥ 2 series; label selectively (end value, extremes), never every point.
- Crosshair tooltips (`axisTooltip`) on lines/areas, item tooltips on bars/dots/cells.
- Every chart needs a meaningful `ariaLabel`; both light and dark mode must look right.

## Verification (run before calling a page done)

- `pnpm -C web exec tsc -b --noEmit` · `pnpm -C web exec eslint . --max-warnings=0` ·
  `pnpm -C web exec prettier --check .`
- `bash scripts/e2e_dev.sh <api-port> <web-port> "page <name>"` — all four variants
  (desktop/mobile × dark/light) must pass: charts drawn with data, maps loaded, no console errors,
  no horizontal overflow, no serious/critical axe violations.
- Look at the screenshots in `artifacts/screenshots/<variant>/<page>.png` and fix what looks off
  (overlapping or clipped labels, cramped or empty areas, illegible text in either theme).
